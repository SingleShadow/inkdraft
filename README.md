# 墨稿 InkDraft

个人自用的网文写作工具。本地优先，数据全在你自己机器上，不联网也能写。

对应设计文档：`../novel-writer/网文写作工具-自用版方案-v0.5.html`（v0.5 为方案基线，W1–W3 已实现）。

---

## 快速开始

```bash
npm install

# 方式 A：生产模式（推荐日常使用，单端口 8787）
npm run build
npm start
# → http://localhost:8787

# 方式 B：开发模式（改代码热更新，Vite 5173 + API 8787）
npm run dev
# → http://localhost:5173
```

自检：`npm run smoke`（会启动临时服务，在**临时数据目录**里跑一遍建选题→开书→写章→快照→导出→落盘校验，不碰真实稿件）。

---

## 使用流程

```
首页 → 写一句话创意 → 选题卡（填题材/平台/钩子/对标/自评）→ 用它开书 → 填书名 → 写第一章
```

选题与作品是两件事：**选题是「写什么」，作品是「写出来的东西」**。
一个选题开一本书；没想清楚的选题留在灵感池，放弃了也不删（底部「已放弃」可找回或永久删除）。

> 早期直接建的作品没有关联选题，可在写作页顶栏「选题」面板里补关联（会自动继承题材与目标字数）。

---

## 关于控制台的 `Cannot redefine property: ethereum`

这是浏览器钱包插件（MetaMask / OKX 等）注入 `window.ethereum` 时由插件自己的脚本抛出的，**与本应用无关**
（本应用构建产物与依赖中不含任何 ethereum 相关代码）。`index.html` 里只过滤这一条报错，其余异常照常抛出。

同时加了 ErrorBoundary：真出渲染异常会显示错误详情而不是白屏。

## W2 已实现（设定库：人物 / 世界观 / 大纲）

写作页顶栏「设定」打开右侧面板，三个 Tab：

| Tab | 说明 |
|-----|------|
| **人物** | 人物卡：姓名 / 身份（主角·配角·反派…）/ 性别 / 年龄 / 外貌 / 性格 / 背景 / 目标动机 / 弱点 / 口头禅 / 弧光 + 人物关系（对象·关系·备注）。左侧列表切换，改动 800ms 自动保存 |
| **世界观** | 按分类整理条目（力量体系 / 地理 / 势力 / 历史 / 物品 / 习俗 / 其他），每条标题 + 描述 |
| **大纲** | 自引用树（卷纲 → 章纲 → 片段，深度 ≤4）。每节点可填要点、目标字数，并**关联到真实章节**；支持加下级、上下移、删除（含下级） |

设定库是 **W3 AI 续写的上下文来源**：后端 `buildSettingContext()` 已能把「人物 + 世界观 + 大纲」序列化成一段前缀，续写时注入模型（这正是解决番茄「人设崩塌」拒签硬伤的关键）。
数据单独存 `data/works/<id>/settings.json`，与正文隔离，避免污染 `work.json`。

## W3 已实现（AI 续写 + 投稿前自检）

> 前提：复制 `.env.example` 为 `.env` 并填 `INKDRAFT_AI_KEY`（兼容 OpenAI 协议的任意模型，可指向 DeepSeek / 通义 / 智谱 / 本地 Ollama）。不填则续写不可用，其余功能照常。

**AI 续写（草稿需你改写）** —— 顶栏「续写」或 `Ctrl/Cmd+J` 触发：

1. 填续写意图（可选）+ 选爽点类型 + 长度（200/500/1000 字），模型基于「设定库上下文 + 前文」生成 2 个候选方向；
2. 进入**改写工作台**：左 AI 草稿（只读）、右你的版本，**实时显示改写率**；
3. 改写达标（番茄 ≥70% / 起点 ≥80% / 晋江 ≥95%）后插入正文 → 该段带 `aiSpan` 标记（编辑器内淡黄高亮），并计入本章 AI 占比。

**三条硬护栏（对应投稿合规）**：

- 标记不可擦除：哪段是 AI 起草，肉眼与元数据都能看到，未来投稿被抽检时可自证；
- 章节状态栏与自检报告显示 AI 占比，平台阈值绿/黄/红一目了然；
- 不做「一键降 AI 率 / 去 AI 味」——那是换模型再洗一遍，治标不治本，反而把工具变成规避手段。

**投稿前自检报告** —— 顶栏「自检」：总字数、AI 占比（按平台阈值）、敏感词 / 违规词命中、格式灌水（连续重复字、重复标点）、各章明细。
本地词库起步很小（`server/sensitive.json`），请自行补充完整。

## W3+ 已实现（一键成书 · 五段式流水线）

顶栏「✦ 一键成书」打开写作向导，从一句话创意直接推到正文：

1. **创意 / 书名** — 一句话创意 + 频道题材 + 目标字数，可 AI 起名；
2. **大纲 / 人物** — 生成总纲（主线、阶段、暗线、结局）与人物卡，自动写进设定库；
3. **分卷 / 卷纲** — 把总纲拆成 3–5 卷，每卷有目标、冲突与爽点；
4. **章纲 / 章节目录** — 每卷生成章节目录与本章大概剧情，可逐条手改；
5. **写正文** — 按章生成细节，写成真实章节并保留 AI 标记，支持进度显示与中途停止。

三层大纲体系：**总纲 → 卷纲 → 章纲**，每层 AI 生成后可编辑，再作为下一层上下文，避免跑偏和烂尾。计划断点落盘在 `works/<作品id>/book-plan.json`，关掉应用再打开可续写；已生成的卷不会被重复覆盖。

> 一键成书同样需要配置 `INKDRAFT_AI_KEY`；生成的是**可继续改写的草稿**，不是直接投稿的终稿。

## 数据在哪、怎么不丢

```
inkdraft/
  data/                 ← 全部作品（同时是一个 Git 仓库）
    topics.json         ← 选题库（作品的上游）
    works/<作品id>/
      work.json         ← 作品元信息与卷章结构（含 topicId、目标字数、日更目标）
      settings.json     ← 设定库：人物 / 世界观 / 大纲（W2，W3 续写上下文来源）
      chapters/<章>.json ← 正文结构化内容
      chapters/<章>.md   ← 正文纯文本（Git 镜像，人也能直接读）
      snapshots/<章>/<时间戳>.json
  backups/<时间戳>/data  ← npm run backup 的产物
```

五道防线：

1. **实时落盘** — 自动保存 + 原子写（临时文件 rename）
2. **章节快照** — 手动 / 每 10 分钟
3. **Git 镜像** — `data/` 自动提交，`git log` 可回溯任意历史
4. **异地备份** — `npm run backup`，或整个目录交给网盘/第二块硬盘
5. **导出演练** — 每月导一次 txt 并确认能打开

> ⚠️ **不要把 `data/` 直接放进网盘实时同步目录**——并发写入可能损坏文件。要同步就同步 `backups/` 里的副本。

### 恢复演练（请现在就做一次，5 分钟）

```bash
# 1. 打开作品写几句话，确认顶栏显示「已保存」
# 2. 故意删掉一章
# 3. 从快照恢复：右侧「快照」面板 → 找到时间点 → 恢复
# 4. 从 Git 恢复（快照也丢了的情况）
cd data && git log --oneline        # 找到提交
git show <hash>:works/<作品id>/chapters/<章>.md
# 5. 确认内容一致后，才算演练合格
```

## 快捷键

| 键 | 作用 |
|----|------|
| `Esc` | 专注模式开关 |
| `Ctrl/Cmd + S` | 立即保存并留一个快照 |

## 技术说明

- **零外部服务依赖**：Node 22 内置 `http` + JSON 文件存储（没用数据库，避免安装与迁移成本；需要全文检索时再换存储 adapter，`server/store.js` 已隔离）
- **前端**：React 18 + Vite + Tiptap（ProseMirror），无 UI 框架
- **正文存结构化 JSON，不存 HTML** — 便于将来做 diff、迁移与 AI 片段标记
- **AI 适配器兼容 OpenAI 协议**：`server/ai.js` 零额外依赖；敏感词与自检逻辑（`server/check.js`）纯本地、零成本
